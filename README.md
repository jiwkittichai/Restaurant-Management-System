# Restaurant Management System

## ฟังก์ชันหลัก

- ระบบเข้าสู่ระบบและกำหนดสิทธิ์ตามบทบาท
- ระบบจัดการบัญชีพนักงาน
- ระบบรับออเดอร์แบบทานที่ร้านและซื้อกลับบ้าน
- ระบบจัดการโต๊ะและคิวซื้อกลับบ้าน
- ระบบหน้าจอครัวและติดตามสถานะอาหาร
- ระบบจัดการเมนูและหมวดหมู่
- ระบบวัตถุดิบ สูตรอาหาร และการตัดสต็อก
- ระบบบันทึกสถานะและช่องทางการชำระเงิน
- ระบบรายงานยอดขายและเมนูขายดี
- ระบบบันทึกประวัติกิจกรรมของพนักงาน

## เทคโนโลยีที่ใช้

- **Core Framework:** Next.js
- **Frontend & UI:** React, TypeScript, Tailwind CSS
- **Backend & API:** Next.js Route Handlers, Node.js
- **Database & ORM:** MySQL, Prisma ORM
- **Infrastructure & Tools:** Docker, MinIO, phpMyAdmin

## แนวทางจัดโครงสร้างและ Refactor

- เก็บฟีเจอร์ไว้กับเส้นทางของตัวเอง เช่น `dashboard/products` โดยคง `page.tsx`, `create/page.tsx` และ `[id]/edit/page.tsx` เพื่อให้หาแต่ละหน้าได้ชัดเจน
- `page.tsx` ที่มีไม่กี่บรรทัดอาจเป็นจุดเชื่อม route กับ component ไม่จำเป็นต้องรวมกลับ ส่วนหน้าที่ยังอ่านง่ายสามารถเก็บ state และ handlers ใน `page.tsx` ได้
- `_components` ในฟีเจอร์เก็บ UI ของฟีเจอร์นั้น ทั้งที่ใช้หน้าเดียวและหลายหน้า แยกเมื่อเป็นส่วนงานชัดเจน เช่น ตาราง ฟอร์ม หรือ dialog ไม่แยกทุก input/button
- PageClient หรือ form controller ดูแล state, โหลดข้อมูล และ handlers ของหน้า ส่วน UI ที่แชร์รับเฉพาะข้อมูลที่ต้องใช้ ไม่ควบคุมขั้นตอนบันทึกของทุกหน้า
- แชร์ types เฉพาะข้อมูลที่มีความหมายเดียวกัน เช่น `products/types.ts` เก็บช่องฟอร์มร่วม ส่วนรูปเดิมและสถานะพร้อมขายของหน้าแก้ไขอยู่ใน type ของหน้าแก้ไขเอง ฟอร์มกลางส่งเฉพาะค่าที่เปลี่ยนกลับไปให้หน้ารวม state
- `dashboard/_components` เก็บส่วนที่ใช้ระดับ dashboard เช่น Header, Sidebar และ billing ซึ่งโต๊ะ/ซื้อกลับบ้านใช้ขั้นตอนชำระเดียวกัน ส่วน `overview` เป็นส่วนของหน้าภาพรวม ไม่ใช่ UI กลางทุกฟีเจอร์
- ไม่รวม Filter Card, สถานะ, ฟอร์ม หรือขั้นตอนสั่งอาหารเพียงเพราะหน้าตาคล้ายกัน หน้าพนักงานกับหน้าลูกค้า QR มีเงื่อนไขต่างกัน เช่นเดียวกับวันที่ของ audits/reports และการแสดงเงิน/คำนวณเงินจริง
- ไม่สร้าง generic CRUD, universal form หรือ custom hook สำหรับทุกหน้าโดยไม่มีการใช้ซ้ำที่ชัดเจน helper เล็กที่ใช้จุดเดียวเก็บในไฟล์เดิมได้ ส่วน `types.ts`/`utils.ts` ที่หลาย component ใช้ร่วมกันคงไว้ได้
- โค้ด server ที่ใช้ร่วมกันอยู่ใน `src/lib` เช่น Prisma, auth และการส่งออเดอร์ ไม่ย้าย transaction หรือการตรวจสิทธิ์ไปใน UI การตรวจบทบาทใน navigation เป็นเพียงฝั่งหน้าจอ ไม่ทดแทน API authorization
- ไม่ลบ API, migration หรือ script เพียงเพราะไม่มี frontend import เพราะอาจเป็น entry point ที่ถูกเรียกจากภายนอก

ก่อนรวมโค้ด ให้พิจารณาว่าเมื่อฟีเจอร์หนึ่งเปลี่ยน อีกฟีเจอร์ควรเปลี่ยนตามด้วยหรือไม่ หากไม่ใช่ ให้แยกไว้ แม้มีโค้ดบางส่วนคล้ายกัน และจัดรูปแบบโค้ดให้อ่านง่ายก่อนตัดสินใจแตกไฟล์เพิ่ม

ตรวจ regression ของขอบเขตโค้ดกลางด้วย dependencies ที่มีอยู่แล้ว:

```bash
npx tsx --test tests/*.test.ts
npx tsc --noEmit
npm run build
```

การตรวจเหล่านี้ไม่แทนการทดสอบใช้งานจริง เช่น create/edit เมนู รับออเดอร์ ชำระเงิน และพิมพ์บิล

## สิ่งที่ต้องติดตั้ง

- Node.js
- Docker Desktop
- Git

## การติดตั้งโปรเจค

### 1. ติดตั้ง Dependencies

```bash
npm install
```

### 2. สร้างไฟล์ `.env` จากตัวอย่าง

```bash
cp .env.example .env
```

### 3. สร้าง Prisma Client

```bash
npx prisma generate
```

### 4. เปิดบริการ Docker

```bash
docker compose up -d
```

### 5. สร้างโครงสร้างฐานข้อมูล

สำหรับการติดตั้งใหม่บนฐานข้อมูลว่าง: baseline รวมช่อง `PlatformSettings.logoUrl` แล้ว ไม่ต้องรัน migration เพิ่มโลโก้แยกต่างหาก

หากฐานข้อมูลเดิมเคยใช้ migration ก่อนการรวมนี้ อย่ารันขั้นตอนนี้โดยถือว่าเป็นการอัปเกรดตามปกติ การติดตั้งโปรเจคหรือสร้าง container ใหม่ไม่ได้ทำให้ฐานข้อมูลใน Docker volume เดิมว่าง ต้องเลือกฐานข้อมูลใหม่ หรือสำรองข้อมูลและวางแผนย้ายฐานข้อมูลเดิมก่อน

```bash
npx prisma migrate deploy
```

### 6. สร้าง MinIO Bucket

```bash
npm run minio:init
```

คำสั่งนี้จะสร้าง Bucket ชื่อ `products` สำหรับจัดเก็บรูปภาพเมนู และสามารถรันซ้ำได้โดยไม่ลบรูปเดิม

### 7. เปิดเว็บไซต์

```bash
npm run dev
```

เปิดเว็บไซต์ที่:

```text
http://localhost:3000
```

## สั่งอาหารผ่าน QR ประจำรอบโต๊ะ
### ทดลองสแกนจากมือถือ

- เปิดเว็บด้วย `npm run dev -- --hostname 0.0.0.0` และให้มือถืออยู่ใน Wi-Fi เดียวกับคอม
- หากเปิดหน้าพนักงานจาก localhost ในโหมดพัฒนา ระบบใช้ LAN IP ใน QR ให้อัตโนมัติ
- หากมีหลายการ์ดเครือข่าย/VPN ให้ระบุ `QR_PUBLIC_BASE_URL=http://<IP ของคอม>:3000` ใน `.env` แล้วเริ่มเซิร์ฟเวอร์ใหม่
- เมื่อโฮสต์จริง ให้ตั้ง `QR_PUBLIC_BASE_URL` เป็นโดเมน HTTPS ที่ลูกค้าเข้าถึงได้ การส่งลิงก์ให้เพื่อนนอก Wi-Fi ร้านต้องใช้ URL ที่เข้าถึงจากอินเทอร์เน็ตได้
- รูปเมนูจาก MinIO ในหน้าลูกค้าโหลดผ่านเว็บร้านโดยอัตโนมัติ รองรับ URL เดิมที่เป็น localhost/127.0.0.1 โดยมือถือไม่ต้องเข้าถึงพอร์ต MinIO โดยตรง
